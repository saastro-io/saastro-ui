# create-saastro

CLI tool to scaffold new SaastroCMS projects. Built with commander + enquirer.

## Structure

```
create-saastro/
├── src/
│   └── index.ts                # CLI entry point
├── templates/
│   ├── blog/                   # Blog template (posts collection)
│   ├── docs/                   # Documentation template
│   ├── minimal/                # Minimal template
│   ├── portfolio/              # Portfolio template
│   └── common/                 # Shared files (admin routes, API routes, wrangler.toml)
├── package.json                # bin: create-saastro -> ./dist/index.js
├── tsup.config.ts              # ESM, node18 target, shebang banner
└── README.md
```

## How It Works

1. `npx create-saastro [project-name]`
2. Commander parses args (`-t`, `--template`, `--npm/pnpm/yarn/bun`, `-y`, `--no-git`, `--no-install`)
3. Enquirer prompts for missing values
4. Copies template + common files (template wins on conflict)
5. Generates: `package.json`, `astro.config.mjs`, `.env.example`, `tsconfig.json`
6. Optionally initializes git and installs dependencies

## Key Notes

- Package manager auto-detected from `npm_config_user_agent`
- `-y` flag uses defaults (blog template, auto-detected pm)
- Project name validation: letters, numbers, dashes, underscores only
- Existing non-empty directories cause exit with error

## Consumers

- End users via `npx create-saastro`
- No internal monorepo consumers

## Known Gaps

- No tests (no unit or integration tests)
- Portfolio template missing `[...slug].astro` dynamic route for project detail pages
- Templates reference `@saastro/cms` integration which must be separately installed
- Template content may be outdated relative to current CMS API
- No template validation (templates not checked against current schema)
- Single source file (422 lines) — could benefit from splitting for maintainability
