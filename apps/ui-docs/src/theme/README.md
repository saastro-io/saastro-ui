# `src/theme/` — tema de documentación VENDORIZADO

Copia local del tema de docs. **No es una dependencia npm a propósito.**

## Por qué

Este sitio consumía `@saastro-io/docs-theme` + `@saastro-io/shell` desde GitHub
Packages. Eso costaba más de lo que aportaba:

- un cambio de 2 líneas de CSS exigía publicar el paquete y subir 4 consumidores;
- la publicación se rompió (PAT caducado → 401) y el arreglo quedó atascado meses;
- el paquete acabó **duplicado** en dos repos, con la copia que publicaba
  congelada en abril y la copia viva sin poder publicarse;
- los 4 consumidores derivaron (este sitio se quedó en `docs-theme@0.2.0`
  mientras los otros iban por 1.0.0).

La regla que sale de ahí: **lógica con contrato → paquete versionado;
presentación → copy-in**. Es lo mismo que ya hace el registry de bloques, y lo
que hace `saastro-character/docs`, que también lleva su tema vendorizado.

## Origen

Nació como copia del tema de docs de saastro-relay (la versión que ya había
internalizado los componentes de `shell` en `internal/`). Ese repo se apagó al
sustituirlo saastro-office, así que aquí no queda dependencia de él: solo el
dato de dónde salió. Cambios propios al traerlo:

- `internal/Footer.astro`: fuera la atribución "Generated by saastro-relay",
  que el original estampaba sin forma de quitarla.
- `components/Sidebar.astro`: el rail se despliega de verdad en móvil. Antes el
  header pintaba una hamburguesa que no hacía nada.

## Qué NO tocar aquí

Los tokens del sitio no viven en este tema: los redefine
`src/styles/saastro-ds.css` (el Saastro Design System). Este `theme/` aporta
estructura y chrome; el color y la tipografía vienen de esa capa, que se aplica
después por orden de cascada.
